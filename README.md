# QR受付システム (QRReceptionSystem)

庁内ネットワークで利用する、**静的HTML・JavaScriptのみのQR受付システム**。バックエンド・外部API・CDN・インターネット接続は使いません。

## 使い始める

1. このリポジトリをZIPで取得し、ファイルと `vendor/` を同じディレクトリ構造で庁内Webサーバーに配置する。
2. **`index.html` を開く**（`app.html` に移動）。
3. 総合管理画面で「＋ 新規イベント」を作成し、事前準備で参加者を登録する。
4. 事前に参加者のQRを発行し、当日は「受付」から受付区分を選択してQRを読む。
5. 重要な変更・イベント終了のタイミングで「全イベントJSONバックアップ」を保存する。

**必ず実際の庁内PC・Webサーバーで事前検証してください。** 旧検証版では現在の環境でHTTPカメラ読み取りを確認済みですが、異なるブラウザ・端末ではHTTPS等のセキュアコンテキストを要求する場合があります。

## 初期実装の範囲

| 項目 | 状態 |
| --- | --- |
| 総合管理／イベント一覧 | 実装済み（開催日・イベントIDの昇降順、日付範囲・イベント名の絞り込み） |
| イベント作成・複製・削除 | 実装済み。複製は設定だけ、名簿・受付結果はコピーしない |
| イベント設定 | 実装済み（開催日・分類・区分設定・任意2項目の自由入力／有無／選択肢） |
| 参加者登録 | 実装済み（個別・CSV、列マッピング・取込プレビュー・職員番号／参加者IDによる既存者の更新） |
| QRコード | イベント専用QRの個別PNG・**全参加者PNG＋宛先CSVのZIP一括発行**・A4印刷プレビュー |
| 紙の受付名簿 | 受付区分ごとのA4縦チェックリストを事前準備／当日受付の両画面から印刷可能 |
| 当日受付 | QR照合、重複防止、区分別タイムスタンプ、手動受付、飛び入り追加、参加対象外の確認受付、取消理由・再受付履歴 |
| 受付状況のタブ | **未受付**（事前登録者）／**受付済み**（QR・手動・当日登録を含む）を選択中の受付区分ごとに切替。氏名・所属・受付日時を表示 |
| localStorage | イベント単位のデータ保存。PC・ブラウザプロファイル・オリジンごと |
| JSON | 全イベントの一括バックアップ、形式検証・重複確認付き復元 |
| 全データ削除 | 総合管理 → データ管理から全イベント・名簿・受付履歴を一括消去（確認文字入力・最終確認付き） |
| CSV出力 | 名簿、区分別結果、横断参加者一覧、横断区分別詳細、**受付変更履歴**、メール宛先対応表 |
| ヘルプ | [help.html](./help.html) に独立した操作案内 |
| 受付履歴の確認 | 参加者編集画面で初回受付・取消・再受付の時刻／取消理由を表示 |
| QRの職員共通化／複数PC同期／アクセス認証 | 未実装・将来検討 |

**注意:** QR読み取りとJSON保存／復元は利用環境で動作確認済みです。今回追加したZIP出力、CSV列マッピング／更新、任意項目設定、受付履歴表示については**実ブラウザでの操作・ファイル出力検証がまだ完了していません**。テストデータで検証してから本番利用してください。

## 紙の受付名簿（非常時の代替受付）

- 事前準備の「結果・出力」から受付区分を指定して印刷、または当日受付画面で現在選択中の受付区分を印刷する。
- A4縦、1ページ最大20行。区分の参加対象である全参加者（受付済みを含む）を氏名順に掲載。除外済みの参加者は載せない。
- 参加者ID、職員番号、氏名、所属、印刷時点の電子受付状況、**手書きチェック欄と時刻・備考欄**を設ける。最後に**当日追加用の空欄4行**を付ける。
- 電子受付済みの人は「済＋時刻」と表示し、紙チェック欄は別に空欄のままにする。
- **PCの故障に備え事前印刷を推奨。** 印刷はデータを変更せず、紙のチェックは自動反映されない。復旧後に紙の受付結果を確認して手動受付などで補完する。印刷物は庁内の個人情報管理ルールに従う。

## 保存と復元

- 保存先は `localStorage` の `QRReception:index:v1`（ID一覧）と `QRReception:event:v1:<イベントID>`（イベントごと）。
- JSONはバックアップ用で、個人情報・発行済みQRの識別子・受付履歴・採番情報を含む。ファイルは庁内ルールに従い厳重に管理する。
- 復元では既存のイベントを**保持（既定）／上書き**から選ぶ。上書きすると既存の受付履歴が差し替わるため確認画面を設けている。
- CSVはExcel用。参加者一覧はイベント×参加者、区分別詳細はイベント×参加者×受付区分が1行。
- **全イベントJSONの対象はイベント一覧の検索条件とは無関係**。同じオリジン内のアプリが管理するすべてのイベントを出力する。
- **全データ削除**は、当アプリの `QRReception:index:v1` と `QRReception:event:v1:` で始まる保存項目のみを対象とする。ブラウザ全体のlocalStorageを消去しない。削除前にJSONバックアップを取得すること。
- 旧 `scanner-prototype.html` のデータは別の保存領域なので、新アプリのデータへ自動移行しない。

## CSV参加者登録

1. CSVファイルを選び「取り込み内容を確認」を押します。
2. 項目名・職員番号・所属・受付区分などの**列対応をプレビューで確認／変更**します。
3. 既登録者の扱いを「スキップ（初期値）」または「情報を更新」から選択します。
4. 新規・更新・スキップ件数を確認し、確定します。保存エラー時は追加／更新を確定しません。

- **既存者の照合には、同じイベント内の参加者IDか職員番号を使用**します。氏名だけで同一人物とは判断しません。
- 更新時は参加者ID・QR識別子・受付履歴を維持。CSVに割り当てていない列の既存値や受付区分は維持します。
- 異なるイベントIDのデータや、参加者IDと職員番号が矛盾する行、受付済み区分を対象外へ変更する行は拒否します。
- CSVからの更新は氏名・所属・メール・任意項目・参加予定などの登録情報に対するもので、受付時刻を上書きしません。

- 最低限 `氏名` または `name` 列を用意する。
- 任意の列名：`職員番号` / `staff_id`、`所属` / `department`、`メール` / `email`、設定した任意項目の表示名。
- 受付区分名（例：`午前`、`午後`）を列見出しにし、参加予定は `○` または `1` 等で指定する。
- 1区分だけのイベントでは区分列がなければ全員を参加対象にする。**複数区分がある場合、区分列を省略するとその区分は参加対象外**になる。
- UTF-8（BOM対応）。Shift_JISは文字化けを検知した場合に代替デコードを試みる。
- 任意項目の「有・無」はCSVの ○／×・1／0 などを「有／無」に正規化します。「選択肢」は登録された選択肢との一致を検証します。

## ファイル

| ファイル | 役割 |
| --- | --- |
| `index.html` | アプリ入口（`app.html` へ遷移） |
| `app.html`・`app.css`・`app.js` | 実際に保存・操作するアプリ |
| `app-support.js` | オフラインでのZIP生成・CSV文字コード／列処理補助 |
| `help.html` | ヘルプ・操作説明 |
| `wireframe.html` | 旧デザイン検証用（データ保存はしない） |
| `scanner-prototype.html` | 従来のQR読み取り検証版（独立した保存領域） |
| `issue.html` | 単票QR発行検証版（本アプリの名簿とは連動しない） |
| `vendor/` | QRコード読取・生成用ライブラリ（各ライセンス同梱） |
| `docs/基本方針.md` | 設計上の決定事項・今後の拡張方針 |

既存の試作品を残すため、新しいアプリ用に `app.*` を追加しています。
