# QR受付システム (QRReceptionSystem)

庁内ネットワークで利用する、**静的HTML・JavaScriptのみのQR受付システム**。バックエンド・外部API・CDN・インターネット接続は使いません。

## セキュリティ検知に関する調査記録

2026-11-01、GitHubからダウンロードしたソースZIP内の `app-support.js` がMicrosoft Defenderで `Trojan:Script/Wacatac.B!ml` と検知されたとの報告がありました。**安全性・誤検知の判定は未確定**です。調査済み事項、未確認事項と次の検証手順は **[Defender検知調査（2026-11-01）](docs/Defender検知調査_2026-11-01.md)** を参照してください。検知を無視して許可・除外することは推奨しません。

## 使い始める

1. このリポジトリをZIPで取得し、ファイルと `vendor/` を同じディレクトリ構造で庁内Webサーバーに配置する。
2. **`index.html` を開く**（`app.html` に移動）。
3. 総合管理画面の「＋ 最初のイベントを作成する」（2件目以降は「＋ 新規イベント」）で作成する。
4. 画面上部の「次にやること」に沿って ①設定 → ②参加者登録 → ③QR発行 → ④紙名簿印刷 と進める。当日は「▣ 受付」から受付開始前の確認を済ませ、QRを読む。
5. 重要な変更・イベント終了のタイミングで「全イベントJSONバックアップ」を保存する。

**必ず実際の庁内PC・Webサーバーで事前検証してください。** 旧検証版では現在の環境でHTTPカメラ読み取りを確認済みですが、異なるブラウザ・端末ではHTTPS等のセキュアコンテキストを要求する場合があります。

## 紙の受付名簿（非常時の代替受付）

- 事前準備の「結果・出力」から受付区分を指定して印刷、または当日受付画面で現在選択中の受付区分を印刷する。
- A4縦、1ページ最大20行。区分の参加対象である全参加者（受付済みを含む）を氏名順に掲載。除外済みの参加者は載せない。
- 参加者ID、職員番号、氏名、所属、印刷時点の電子受付状況、**手書きチェック欄と時刻・備考欄**を設ける。最後に**当日追加用の空欄4行**を付ける。
- 電子受付済みの人は「済＋時刻」と表示し、紙チェック欄は別に空欄のままにする。
- **PCの故障に備え事前印刷を推奨。** 印刷はデータを変更せず、紙のチェックは自動反映されない。復旧後に紙の受付結果を確認して手動受付などで補完する。印刷物は庁内の個人情報管理ルールに従う。

## 職員番号QR・参加者登録（改修版）

- QR発行は「個別発行」「一括発行」の切替式。一括ZIP・10面印刷は一括発行タブだけに表示し、個別発行画面の重複ボタンをなくす。個別はプルダウンまたは前／次ボタンで参加者を変更し、現在位置を表示する。最初／最後の参加者では対応する矢印を無効にする。
- 個別PNG・一括ZIP内PNGは**A4・10面印刷と同じ横型（91×55mm相当）**のカード画像で、QR・氏名・職員番号・グループをまとめて表示する。QRの中身は従来どおり職員番号のみ。
- 個別印刷は選択した1名だけをA4の最初の位置に印刷。一括印刷は従来どおり10件単位で改ページ。プレビュー以外の印刷レイアウトは維持する。


- QRのペイロードは**職員番号だけ**。例：職員番号 `00123` → QR内容も `00123`。職員番号は**半角英数字**（例：`00123`、`u70003`。ハイフン不可）を**文字列**として扱い、先頭ゼロを保持する。全角入力は半角に変換し、照合・重複判定では大文字・小文字を区別しない。イベント・氏名・接頭辞は含めない。職員番号QRは本人認証ではない。
- QR発行対象は**職員番号が登録された参加者のみ**。職員番号がない方も名簿登録・当日の手動受付は可能。QR発行画面には発行対象人数と対象外人数を表示する。
- 発行済みQRを現在開いているイベントの名簿と職員番号で照合して受付する。重複する職員番号の登録を拒否する。
- 紙のQR受付票はA4縦、**2列×5段、10件ごとに改ページ**。QRの周囲に白余白を取り、印字は「氏名」「番号だけ」「グループ（入力時のみ）」とする。グループは任意入力。
- 個別参加者登録、CSVテンプレート、CSV列対応、表の貼り付け（**タブ区切りまたはカンマ区切りを自動判定**）はいずれも新しいデータ項目に対応。引用符で囲まれたカンマや改行も処理する。メールアドレス入力・出力は廃止。
- イベント設定の受付区分を追加・削除しても画面最上部へスクロールせず、追加した区分の近くに結果を表示する。
- イベント設定画面は「基本情報」「受付区分」「追加の登録項目」を独立したカードに分ける。区分の候補は区分カード内、追加項目の候補は追加項目カード内に表示する。候補は空き枠にのみ追加し、設定済みの名前は重複登録しない。過去イベントの候補はこのPCに保存されたイベントを参照する。
- 追加の登録項目（最大2つ）では項目名・入力方法・選択肢とプレビュー、保存済み／未保存を確認できる。画面上は「はい／いいえ」と表示し、内部値は従来の「有／無」を保持する。
- **今回は旧QR・旧JSONとの互換を要件としない。** 以前のテストデータは全イベントJSONを保管したうえで、必要に応じて総合管理の全件削除を使って整理する。
- 紙QRの読み取りテストは、印刷して実際にスキャンできるかを簡単に確認する方法とする。

## 保存と復元

- 保存先は `localStorage` の `QRReception:index:v1`（ID一覧）と `QRReception:event:v1:<イベントID>`（イベントごと）。最終バックアップ日時・受付音設定・手順の進み具合（QR発行・紙名簿印刷の実行記録、当日の開始前確認）は `QRReception:meta:v1`（JSONには含めない）。
- JSONはバックアップ用で、個人情報・職員番号・受付履歴・採番情報を含む。ファイルは庁内ルールに従い厳重に管理する。
- 復元では既存のイベントを**保持（既定）／上書き**から選ぶ。上書きすると既存の受付履歴が差し替わるため確認画面を設けている。
- CSVはExcel用。参加者一覧はイベント×参加者、区分別詳細はイベント×参加者×受付区分が1行。
- **全イベントJSONの対象はイベント一覧の検索条件とは無関係**。同じオリジン内のアプリが管理するすべてのイベントを出力する。
- **全データ削除**は、当アプリの `QRReception:index:v1`・`QRReception:meta:v1` と `QRReception:event:v1:` で始まる保存項目のみを対象とする。ブラウザ全体のlocalStorageを消去しない。削除前にJSONバックアップを取得すること。
- 旧 `scanner-prototype.html` のデータは別の保存領域なので、新アプリのデータへ自動移行しない。

## 参加者登録画面と名簿の取り込み
- 一括登録は「表データを貼り付け」「CSVファイルを選択」のタブ切替。既存名簿がある場合は一括登録欄を初期状態で閉じ、名簿を確認しやすくする。取込完了時も自動で閉じる。
- ひな形は「ひな形：Excel形式（推奨）／CSV形式」で1行に集約。先頭ゼロの扱いや記入例の説明はⓘヘルプで確認できる。
- 1人ずつ登録は従来どおりのダイアログを開き、任意項目1・2と参加区分ごとのチェックを維持する。
- 名簿一覧は高さ360pxの枠内でスクロールし、25件（初期値）／50件／100件を選べる。検索・参加区分フィルタと前後ページ移動に対応。CSV書き出しは表示ページだけでなく全登録者が対象となる。
- イベント名の下にある「事前準備／当日受付」のモード切替は維持。準備完了バナー内の重複した当日受付ボタンは削除し、上部の切替を案内する。

## CSV参加者登録

1. CSVファイルを選び「取り込み内容を確認」を押します。
2. **「取り込み内容の確認」**ダイアログで、氏名・職員番号・所属・グループの自動列対応と先頭5名のプレビューを確認します。受付区分ごとに「全員を参加予定にする／Excelの列で指定する／指定しない」を選べます。参加者ID・追加項目・既存重複時の扱いは折りたたみ式の詳細設定から変更できます。通常使わない項目は「未使用」と表示し、ⓘヘルプで用途を確認できます。イベントIDの照合欄は廃止しました。必須の氏名列が選ばれていない場合や参加予定がない新規参加者には警告を表示します。
3. 既登録者の扱いを「スキップ（初期値）」または「情報を更新」から選択します。
4. 新規・更新・スキップ件数を確認し、確定します。保存エラー時は追加／更新を確定しません。

- **既存者の照合には、同じイベント内の参加者IDか職員番号を使用**します。氏名だけで同一人物とは判断しません。
- 更新時は参加者ID・受付履歴を維持。QRの内容は現在の職員番号になる。CSVに割り当てていない列の既存値や受付区分は維持します。
- 参加者IDと職員番号が矛盾する行や、受付済み区分を対象外へ変更する行は拒否します。イベントIDはアプリ内部では管理しますが、Excel取り込みの列照合には利用しません。
- CSVからの更新は氏名・所属・グループ・任意項目・参加予定などの登録情報に対するもので、受付時刻を上書きしません。

- 最低限 `氏名` または `name` 列を用意する。
- 任意の列名：`職員番号` / `staff_id`、`所属` / `department`、`グループ` / `group`、設定した任意項目の表示名。
- ひな形は **Excel形式（.xlsx、職員番号の列は文字列設定済み・おすすめ）** とCSV形式を用意。2行目に記入例があり、氏名が「（例）」で始まる行は取り込まない。
- 受付区分の列見出しは `受付区分：午前` の形式（区分名だけの見出しも可）。参加予定は `○` または `1` 等で指定する。
- 1区分だけのイベントはひな形に区分列がなく、全員を参加対象にする（区分列があって空欄でも参加対象）。**複数区分がある場合、区分列を省略するとその区分は参加対象外**になる。
- UTF-8（BOM対応）。Shift_JISは文字化けを検知した場合に代替デコードを試みる。
- 任意項目の「有・無」はCSVの ○／×・1／0 などを「有／無」に正規化します。「選択肢」は登録された選択肢との一致を検証します。

## 追加の登録項目の表示（2026-11-02）

イベント設定で名前を付けた追加項目（最大2件）は、個別参加者の登録・一括取り込みで保存され、以下の画面にも表示されます。

- QR発行の個別プレビュー、個別PNG、一括ダウンロードZIPの画像と対応表CSV、A4・10面印刷。QRに格納される値は従来どおり**職員番号だけ**です。カード上の追加項目は文字数に応じて末尾を省略する場合があります。
- 紙の受付名簿：氏名の下に追加項目を表示。追加項目のある参加者を含む場合は1ページ16行とし、余白を確保します（通常は20行）。
- 当日受付：未受付・受付済み双方の一覧と、QR／手動受付の結果欄。
- 「名前から受付」：設定されている項目だけを列として表示し、列見出しのクリックで昇順・降順に並べ替え。検索対象にも追加します。
- 参加者登録一覧：設定済みの項目を最大2列表示し、文字列検索の対象にも追加します。
- 総合管理の横断検索：イベントごとの追加項目名と値で検索でき、検索結果では氏名の下にその項目名と値を表示します。

**表示ルール：** 項目名を設定していない列は表示せず、各参加者の空欄の値もカード・紙名簿・受付画面では省きます。未入力でも参加者一覧・「名前から受付」では設定済みの列を表示し、セルは「—」にします。はい／いいえ形式の保存値「有／無」は画面上で「はい／いいえ」に読み替えます。既存のJSONデータ構造と受付履歴は変更しません。

**情報公開への注意：** QRカードには追加項目が印刷・配布されます。備考等に個人情報や第三者に開示できない内容が入る場合は、QRカード配布前にイベント設定と入力内容を確認してください。

## イベント引用作成と受付状態のテスト用クリア（2026-11-02）

**イベントの引用作成：** 総合管理の「＋ 新規イベント」から「引用元イベント」を選び、(1) **設定のみ**（受付区分・追加項目・分類）または (2) **設定＋参加者名簿**（氏名・職員番号・所属・グループ・追加項目の値・参加予定）を選べます。イベント行の「⋯ → 複製」からも同じダイアログを開き、これまでどおり初期状態は「設定のみ」です。新規作成画面で引用元を選んだときは名簿コピーが初期選択です。作成先の日付は空欄で、2日目などに合わせて設定してください。新しいイベントID／受付区分ID／参加者IDは採番し直し、元イベントは変更しません。参加者の受付済み状態・受付時刻・取消／再受付の履歴は**複製しません**。除外済みの参加者は複製せず、元イベントの飛び入り参加者は通常の事前登録者としてコピーします。追加の登録項目は最大2件、参加予定は対応する新受付区分へ引き継ぎます。新規のQRは従来どおり職員番号のみのため、同じ職員番号のQRを再利用できます。

**受付状況の一括クリア：** 当日受付の右側一覧下部「↺ 受付状況を一括クリア」を開き、**選択中の受付区分だけ（初期値）／このイベントの全受付区分**から対象を選びます。確認文字「クリア」を入力しないと実行できません。受付済み状態に加え、受付時刻・取消／再受付履歴を含む選択範囲の`checkins`記録を削除します。**元には戻せません。** 操作開始時にはカメラを停止し、確認・クリア後も自動で再開しません。次の読取テストをするときは「カメラを起動」を押してください。必要ならダイアログの「先にJSONを保存」でバックアップしてから実行してください。参加者名簿・参加予定・イベント設定は保持します。飛び入り追加した参加者も削除されないため、不要なテスト登録者は別途整理してください。操作後は未バックアップ状態になります。
