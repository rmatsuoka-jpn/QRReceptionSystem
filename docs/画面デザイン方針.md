# QR受付システム 画面デザイン方針（2026-11-01 作成）

> 当日受付画面のリデザイン（PR #2）で採用した考え方をまとめたものです。総合管理・事前準備などほかの画面を改修するときは、この方針に合わせてください。

## 1. 基本の考え方

### ① 1画面で作業が完結する
- 基準の画面は**ノートPC（1366×768）**。ブラウザの枠とタスクバーを除くと、表示できる高さは**約625px**。
- その画面で使う主要な要素（入力・結果・一覧）は、**スクロールせずに同時に見える**ようにする。
- 一覧のように長くなる部分は、ページ全体ではなく**その枠の中だけ**をスクロールさせる。

### ② 説明文ではなく、ボタンとラベルで伝える
- 画面に長い案内文を置かない。詳しい説明は help.html に移す。
- ボタンは「主ラベル＋小さな補足」の2段にする。
  - 例：［名前から受付］の下に「QRを忘れた方」と添える。
  - 「何ができるか」と「誰のためのボタンか」が一目で分かるようにする。
- 入力欄の見出しは短い名詞にする。例：「受付区分」。

### ③ 1画面に主役は1つ
- その画面で一番大事な情報を、いちばん大きく見せる。当日受付なら「読み取り結果の氏名」。
- 補助的な情報（件数や内訳など）は小さくまとめる。

### ④ 状態は色＋記号で示す
- 成否は、離れた位置からでも分かる色で示す。
- 色だけに頼らず、✓・！・✕ などの記号も添える。

| 状態 | 背景色 | 記号 | 使う場面 |
|---|---|---|---|
| 成功 | 緑 `#1f8a5b`（白文字） | ✓ | 受付完了・保存完了 |
| 注意 | 淡い黄 `#fff3dd`＋黄の枠 `#f0b35c` | ！ | 重複・対象外・要確認 |
| エラー | 赤 `#c2414a`（白文字） | ✕ | 名簿にない・失敗 |
| 待機 | 白（灰色の文字） | — | 操作待ち |

### ⑤ 道具は上部バーに集約し、使う頻度が低いものはしまう
- 画面の切り替え・設定・印刷などは、画面上部の**1本のバー**にまとめる。
- たまにしか使わない項目（例：受付前チェック）は**ポップオーバー**に入れ、押したときだけ開く。
- ポップオーバーは、画面の他の場所を押すと閉じる。
- 状態は**チップ**で常に見えるようにする（例：「未確認 0/4」「✓ 準備OK」）。

### ⑥ 主な操作は大きなボタンで
- 主な操作は、アイコン付きの大きなカード型ボタンにする（`.rx-action`）。
- ON/OFF の設定はチェックボックスではなく**スイッチ**にする（`.rx-switch`）。

## 2. デザインの基本値

| 用途 | 値 |
|---|---|
| メインの色（ボタン・選択中） | `#0a707a`（強調には `#17a398`） |
| 濃い紺（ヘッダー・カメラ枠） | `#17394f`／`#12293a` |
| ページの背景 | `#eef3f6` |
| カード | 白、角丸 14〜16px、枠線ではなく `box-shadow:0 0 0 1px #dfe8ee` で輪郭を出す |
| 本文の文字 | `#183a4f`、補足の文字は `#6c8494` |
| 余白 | カードどうしの間隔は 12px、カードの内側は 14〜22px |
| 文字サイズ | 結果の氏名は `clamp(2.2rem,4.2vw,3.4rem)`、見出しは 1rem 前後、補足は 0.72〜0.8rem |
| フォント | 既存どおり system-ui（游ゴシック・メイリオ） |

> 現在は当日受付専用のクラス（`.rx-*`）として app.css の末尾に入っています。ほかの画面にも広げるときは、まず色などを `:root` の CSS 変数（例：`--c-primary`）にまとめてから使い回すと管理しやすくなります。

## 3. 実装のルール

- **既存の要素IDとJSの処理は変えない。** 見た目は HTML の構造と CSS で変え、JS の変更は表示の連動に必要な最小限にとどめる。
- **CSS は app.css の末尾に、範囲を限定して追加する**（例：`.rx …`、`body.day-mode …`）。ほかの画面に影響を出さない。
- **データ形式（localStorage・JSON・CSV）は変えない。**
- 動作が変わる場合は、PR・README・help.html に明記する。
  - 例：同じQRをかざし続けている間は再処理しない。
- 画面幅の切り替え点は 1100px（2段組みに）と 850px（1段組みに）。高さが 560px 以下のときはページのスクロールを許す。
- 印刷用のスタイル（`@media print`）を崩さない。

## 4. 確認の進め方

1. ヘッドレス Chrome で **1366×625／1366×728／1024×700** の画面を撮影し、崩れていないか見る。
2. カメラが関係する画面は、疑似カメラにQR映像を流して、完了・重複・エラーを再現する。
3. JS のエラーが出ていないことを確認する。
4. `docs/検証チェックリスト.md` に実機での確認項目を追加し、受付PCで確認してからマージする。
