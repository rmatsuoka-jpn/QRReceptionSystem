# QR受付システム 基本方針（2026-10-22 時点）

## 決定事項
- QRコードを参加者一人ひとりに発行し、当日持参してもらい受付で読み取る。
- 庁内の閉域ネットワークで運用し、Webサーバーに静的HTML一式を配置する。
- 外部CDNへの依存をなくし、QR読み取り・発行ライブラリを配布フォルダ内に含める。
- 受付1か所につきPC1台を想定する（同時操作・同期は不要）。

## 技術的な制約と暫定案
- カメラ読み取りのためにはHTTPS配信を原則とする。庁内証明書の信頼設定を確認する。
- サーバーは静的ファイル配信のみとし、受付記録はブラウザのlocalStorageに保存する設計を試す。
- localStorageは業務データの確実な保管手段ではないため、CSVバックアップ運用を必須とする。
- QR内容に氏名などの個人情報を直接含めず、識別番号・ランダムID等を用いる方向で検討する。

## 今後決める事項
1. QRの払い出し方法：名簿CSV取り込み、一括発行、個別発行、印刷／配布手段。
2. QRの識別内容：職員番号かランダムIDか、イベント別IDを使うか。
3. 事前名簿との照合：受付時に氏名や所属を表示するか、未登録者はどう扱うか。
4. 受付データの保全：エクスポート頻度、再インポート、バックアップと復元。
5. 使用ブラウザ／Webサーバー／カメラ装置の組み合わせとHTTPS可否。
6. 個人情報の取扱い、保存期間、操作権限、監査要件。
