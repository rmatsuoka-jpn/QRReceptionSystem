# QR受付システム 初期実装・検証チェックリスト

このチェックリストは、庁内PCと庁内Webサーバーに配置した `index.html`（`app.html`）で、**実際のブラウザ・カメラを用いて確認する項目**です。未実施の項目を完了扱いしないでください。最初は実際の職員名簿ではなくダミーデータで検証します。

## 事前準備

- [ ] 総合管理から新規イベントを作成すると一覧に表示される
- [ ] イベント名・開催日・分類を保存し、ブラウザを再起動しても保持される
- [ ] 受付区分「午前」「午後」を作成し、名称変更できる
- [ ] CSVで氏名・職員番号・所属・午前／午後の参加予定を取り込める（先頭ゼロが保持される）
- [ ] 同一イベント内で職員番号の重複があった場合に二重登録しない
- [ ] 氏名・区分別参加予定の個別編集、参加者の除外ができる

## QR発行・受付

- [ ] 名簿と連動した個別QRを表示・PNG保存できる
- [ ] A4・2列×5行の印刷プレビューで10件／ページになる（倍率100%）
- [ ] 実機カメラでQRが読める（実際のHTTP／ブラウザ環境で確認）
- [ ] QRを読むと「受付完了」と氏名が大きく表示され、未受付者一覧から消える
- [ ] 同じ区分で再読取しても受付時刻が変わらない
- [ ] 午前で受付済みでも午後では別の受付ができ、午後の未受付者一覧に表示される
- [ ] 参加対象外の区分でQRを読んでも勝手に受付済みにならない
- [ ] QR忘れの手動受付・飛び入り登録・受付取消が行える
- [ ] 取消後に再受付したとき、元の初回受付時刻をJSONに残せる

## データ保存・分析

- [ ] ブラウザを閉じて再度開いてもイベントと受付時刻が保持される
- [ ] 総合管理で日付・イベント名の絞り込み、開催日・イベントIDでの並び替えができる
- [ ] 年度・イベント分類で横断参加者一覧を検索できる
- [ ] CSVの1行がイベント×参加者で重複していない（午前・午後の二重計上を防ぐ）
- [ ] 区分別CSVはイベント×参加者×区分で1行となり、受付時刻が日本時間で出力される
- [ ] 全イベントJSONをエクスポートした後、**別の試験用ブラウザプロファイル**へ復元できる
- [ ] 既存イベントがある状態のJSON復元で「保持」「上書き」の違いを確認できる
- [ ] localStorageが書き込めない状態で、受付完了を誤表示しない

## 今回追加した機能の検証（未実機確認）

- [ ] 3人以上の名簿で「QR一括ZIP」を出力し、展開したPNGと `recipient_mapping.csv` の組合せが一致する
- [ ] ZIP内のPNGから実際のQRを読取り、元の参加者を受付できる
- [ ] CSVの列対応を変更し、5行プレビューと登録／更新／スキップ件数を確認できる
- [ ] 職員番号またはイベント内の参加者IDをキーに名簿を更新し、QR識別子・初回受付時刻が変化しない
- [ ] CSVで参加対象区分を変更した際、受付済み区分を誤って対象外にはできない
- [ ] 任意項目を「自由入力」「有・無」「選択肢」に切り替え、個別登録・CSV取込・バックアップ復元で値を保持できる
- [ ] 受付後の取消に理由を入力し、再受付を行っても初回時刻が残る
- [ ] 参加者編集画面に初回・取消・再受付が表示され、履歴CSVに出力される
- [ ] 対象外区分のQRを読み取ったとき、確認を経て「参加対象に変更して受付」が可能
- [ ] 既存の古いJSONバックアップを復元しても任意項目の初期形式（自由入力）が維持される
- [ ] ZIPに500名分のPNGを発行し、ブラウザが停止・強制終了しないか検証する（利用規模に合わせて増減）

JSONバックアップには個人情報とQRトークンが含まれます。テスト終了時の不要データ削除、ファイルの格納先、バックアップの保有期間は庁内ルールを確認してください。
